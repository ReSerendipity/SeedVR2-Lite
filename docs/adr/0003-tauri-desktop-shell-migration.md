# 背景与问题

原对外分发形态为「便携分卷包 + 浏览器打开 http://127.0.0.1:7870」，终端体验存在三类硬伤：

1. 无独立窗口/托盘/系统通知，与「安装即用的普通桌面软件」预期不符；
2. 浏览器标签页生命周期与后端进程解耦，用户关闭标签后推理服务仍在后台运行；
3. 应用代码更新只能靠手工替换文件。

约束：必须与既有 Python 后端共享同一套代码与模型（禁止维护两套推理实现）；目标平台 Windows 优先。

# 评估的备选方案

1. **Tauri v2（Rust 壳 + 系统 WebView2）**——壳体积极小、复用系统 WebView 运行时、单实例/托盘/通知/自动更新插件齐备；代价是引入 Rust 工具链与 WebView 行为差异。
2. **Electron**——生态成熟、接入最快；代价是捆绑整个 Chromium 与一份 Node 运行时，安装包体积与本仓「便携、低占用」定位冲突。
3. **维持便携包 + 浏览器快捷方式**——零新栈；代价是上述 1-3 的体验缺口永久存在，更新仍靠手工。
4. **自研原生 Win32 壳**——无第三方运行时；代价是 WebView 集成、托盘、更新通道全部手写，单人维护不可持续。

# 决策

采用 **Tauri v2**（方案 1）：

- 壳只做「窗口 + 托盘 + 通知 + 拖拽 + 进程看护 + 更新通道」，不复制任何业务逻辑（Python 后端原样复用，桌面版与网页版共享同一套后端与模型）；
- 选型论证与实施过程记录在 `docs/tauri-migration/`（未随仓库分发）；对外可执行的禁区与门禁口径沉淀在 `docs/CODING_STANDARDS.md` 第 5 节；
- 桌面壳机械门禁独立成 `.github/workflows/desktop-shell.yml`（cargo clippy + cargo test + capabilities/permissions 权限镜像哨兵）。

# 实施影响

- 新增 `desktop/`（Rust crate：main / updater / python_process / health_check / tray / window / config / notification / port_manager / drag_drop，依赖锁定见 `desktop/src-tauri/Cargo.lock`）；
- `desktop/src-tauri/tauri.conf.json` 内嵌更新器 minisign 公钥（壳更新信任根，与 ADR-0004 分层）；
- 新增自定义 Tauri 命令须「main.rs 注册 + build.rs 声明 + 提交重生成的 permissions/autogenerated/*.toml」三处同步（desktop-shell.yml 哨兵兜底）；
- 版本兼容：`version.json` 的 `minimum_shell_version` 约束壳与应用代码最低配对。

# 可回滚路径与待验证项

- 壳代码完全位于 `desktop/` 目录，Web 版（`app/integrated_app`）与便携包链路未做删改——回滚 = 停止分发桌面版，Web/便携两条旧链路原样可用；
- 待验证项：macOS/Linux 壳未启用（bundle targets 全开但仅验证 Windows），跨平台验收挂起。
