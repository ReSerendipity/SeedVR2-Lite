# SeedVR2 对外服务合规检查清单（Compliance Checklist）

> 适用场景：将 SeedVR2 Web 服务**公开部署**（公网服务器、对外开放访问）之前逐项检查。
> 纯本地个人使用（`127.0.0.1` 自用）**不触发**下列监管义务，本清单可跳过。
> 最后更新：2026-08-11

---

## 0. 第一步：先判断是否属于"对外提供服务"

| 部署形态 | 是否触发 |
|---|---|
| 本机 `127.0.0.1` / `localhost` 自用 | ❌ 不触发（维持现状即可，勿改绑定地址） |
| 局域网内小范围自用（家庭/办公室） | ⚠️ 边界情形，原则上不构成"面向公众"，但建议保持内网 + 鉴权 |
| 公网服务器 / 对外开放 API / 面向公众 Web 服务 | ✅ 触发，按下表逐项执行 |

---

## 1. 对外部署前检查项

| # | 事项 | 说明 | 状态 |
|---|---|---|---|
| 1 | **服务形态定型** | 明确是"自用工具"还是"面向公众的服务"，二者义务完全不同 | ☐ |
| 2 | **算法备案评估** | 视频/图像修复属深度合成技术（视频编辑类）。具有舆论属性或社会动员能力的深度合成服务提供者须依《互联网信息服务深度合成管理规定》第十九条履行算法备案；是否触发取决于服务形态，建议部署前向属地网信部门咨询或通过互联网信息服务算法备案系统评估 | ☐ |
| 3 | **安全评估** | 依《生成式人工智能服务管理暂行办法》第十七条，具有舆论属性或社会动员能力的生成式 AI 服务须开展安全评估 | ☐ |
| 4 | **备案主体资质** | 备案以服务提供主体名义办理（企业/个人开发者均可），提前准备主体信息、服务信息、算法信息 | ☐ |
| 5 | **AI 内容标识** | 已落地的三层：a) **隐式取证水印**——载荷 `SeedVR2_ReSerendipity_<task_id>` + HMAC-SHA256 签名嵌入 DCT 中频，按输出格式自适应选档（无损 `0.5×1` / JPEG·WebP·视频 `0.05×3`），**落盘后重读产物复验**，缺失按 `runtime.security.watermark_on_failure` 处置（写 `<产物>.provenance.json` 侧车 / 阻断）；b) **文件名标识默认关闭**——四条输出路径（单文件/批量 × 图/视频）一律**沿用输入文件名**（只换扩展名，重名追加 `_1/_2`），既不随机改名也不加标识；对外部署确需文件名级标识时用 `SEEDVR2_EXPLICIT_AI_LABEL=1` 显式开启；c) **元数据机器可读标识**——`ai_generated: true` / `ai_generator: "SeedVR2"` 随 PNG `tEXt:seedvr2_params`、JPEG·WebP·TIFF EXIF UserComment、MP4 容器 comment 一起写。取证反查：`scripts/verify_watermark.py` → `GET /api/system/history/resolve?watermark_payload=`。<br>**明确取舍与后果（须知情）**：① **不在画面叠加可见「AI 生成」角标**——产物是交付级图像/视频，画面内标记破坏观感，故显式标识只落在文件元数据层（文件名层默认关闭）；仅凭肉眼观看图片本身、以及看文件名，都无法识别为 AI 生成，若服务形态触发《标识办法》的显式标注要求，需按业务另行评估。② 元数据与文件名标识**明文可改、重编码即丢**；③ 隐式水印**只对未经再加工的原始产物有效**（缩放/裁剪一次即结构性失效，JPEG 临界存活），传播链上的副本不可鉴定；④ 分发安装各自持本机自动生成的密钥（密钥不随包分发），因此验签只能证明「出自持有该密钥的实例」，**不能跨分发归属到项目方**——那需要在线签发。⑤ 举证依赖原件：`outputs/` 受保留策略（年龄/数量/磁盘水位）自动清理，原件删除后仅剩历史库文字记录 | ☐ |
| 6 | **内容管理** | 配置上传内容过滤与任务审核机制，禁止修复/传播违法信息（淫秽色情、暴力恐怖等），建立举报处理流程 | ☐ |
| 7 | **用户协议** | 已在 `USER_AGREEMENT.md` 中落实用途限制与责任划分；对外服务页面需向用户展示并取得同意 | ☐ |
| 8 | **个人信息保护** | 上传的视频/图像可能含个人信息（人脸等）：a) 告知并取得用户同意；b) 处理完后及时删除或按协议留存；c) 制定隐私政策并公开 | ☐ |
| 9 | **访问控制** | 公网部署必须启用鉴权（API Key/账号），防止被滥用为批量修复通道；确认 CORS 仅允许预期来源（当前默认仅 127.0.0.1） | ☐ |
| 10 | **密钥保护** | `.watermark_key` 仅存于签发机器，禁止进入服务器代码包；服务器上通过环境变量 `SEEDVR2_WATERMARK_KEY` 注入 | ☐ |
| 11 | **日志与溯源** | 保留任务日志（输入哈希、时间、账号）以便配合监管与侵权溯源 | ☐ |
| 12 | **备案后义务** | 备案信息变更（服务停止、主体变更、算法升级）及时办理变更/注销；配合网信部门监督检查 | ☐ |

## 2. 便携包分发检查项（非在线服务）

| # | 事项 | 说明 | 状态 |
|---|---|---|---|
| 1 | **GPL 组件处理** | **决策：便携包不随附 FFmpeg**，引导用户自行安装（置于 PATH，`FFmpegWrapper` 自动查找）；若将来改主意随包分发，须改用 LGPL 构建或履行 GPL 源码提供义务 | ☐ |
| 2 | **密钥排除** | 打包时排除 `.watermark_key`（脚本与构建流程双重校验） | ☐ |
| 3 | **模型合规** | SeedVR2 权重 Apache 2.0，可随包分发；随包附模型许可文本 | ☐ |
| 4 | **署名保留** | Apache 2.0 第 4 条：保留版权声明、LICENSE、NOTICE | ☐ |
